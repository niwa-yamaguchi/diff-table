# 1ファイル登録時のビュワーモード対応 設計書

- 日付: 2026-07-17
- 対象: `excel-diff.html`, `access-diff.html`, `word-diff.html`, `index.html`

## 背景・目的

現状の3つの差分ツールは、ファイルA・ファイルBの両方が読み込まれて初めて
内容の描画（比較結果の表示）が行われる作りになっている。片方のみ読み込んだ
状態では「シートを選ぶと差分が表示されます」等のプレースホルダのままで、
ファイルの中身を一切確認できない。

1ファイルだけ登録した場合でも、そのファイルの中身をそのまま閲覧できる
「ビュワーモード」として機能するようにする。2ファイル目を追加すれば、
現状通りの差分比較モードに自動的に切り替わる。

## 全体方針

- 3ツール共通の考え方で対応する。
  - `state.A` と `state.B` のどちらか一方だけが存在する状態でも、内容描画の
    処理を実行できるようにする（現状は両方揃うまで比較処理そのものが
    走らない）。
  - 表示には既存の比較テーブル／本文描画のレンダリング関数をそのまま流用する。
    相手ファイルが存在しないセル・行は全て「一致（same）」相当として扱い、
    差分色（追加=緑・削除=赤・変更=黄）を付けない通常表示にする。新規の
    専用ビューコンポーネントは作らない。
  - 比較専用のUI部品（サマリー件数、警告メッセージ、モード切替、キー選択など）
    は、1ファイルのみの時は非表示にする。
  - 2ファイル目を追加した瞬間、既存の差分比較ロジック・表示に自動的に
    切り替わる（既存動作は変更しない）。

## ツール別仕様

### Excel差分ビューア（excel-diff.html）

- **1ファイルのみ登録時**（A・Bどちらでも同様）:
  - タブには、そのファイルの**全シート名**を表示する（現状は「A・B双方に
    存在する同名シート」のみタブ化するロジックだが、1ファイルのみの場合は
    そのファイルの全シートを対象にする）。
  - 選択中シートの内容を既存のグリッド描画でそのまま表示する。結合セルは
    そのまま結合表示を再現し、差分色は付けない。
  - サマリー（一致/追加/削除/変更件数）・警告文・「比較するシートを選ぶ」
    チェックボックス（手動ペア選択UI）は非表示にする。
  - PDF出力ボタンは1ファイル表示中も有効のままとする（既存の印刷機能を
    流用）。
- **2ファイル目を追加した瞬間**: 現状通り、同名シートの自動ペアリングに
  よる差分比較に切り替わる。

### Accessビューア（access-diff.html）

- **1ファイルのみ登録時**（A・Bどちらでも同様）:
  - テーブル選択プルダウンには、そのファイルの**全テーブル名**を表示する
    （現状はA・B双方に存在する同名テーブルのみ）。
  - 選択中テーブルの全レコードを既存のグリッド描画でそのまま表示する
    （差分色なし）。
  - サマリー件数・警告文・「複合キー選択」ボタン（行の突き合わせ用UI）は
    非表示にする。複合キーによる行対応付けは差分専用の機能のため。
  - 列ヘッダクリックによるソート機能は1ファイルのみの場合も有効のままと
    する。
- **2ファイル目を追加した瞬間**: 現状通り、複合キーによる行対応付けを
  伴う差分比較に切り替わる。

### Word差分ビューア（word-diff.html）

- **1ファイルのみ登録時**（A・Bどちらでも同様）:
  - 本文を差分ハイライトのないプレーンテキストとして、省略（折りたたみ）
    なしで表示する（既存の「一致行」の見た目を流用。内部実装の詳細は
    下記「実装上の既知の制約」を参照）。
  - サマリー件数・表示モード切替（インライン/左右並列）・「差分行のみ
    折りたたみ」設定は非表示にする。
- **2ファイル目を追加した瞬間**: 現状通り、段落・語単位の差分比較に
  切り替わる。

## 文言更新

- `index.html` のサブタイトル（現状「Access・Excel・Word の2ファイルを
  ブラウザ内で比較（外部送信なし）」）を、1ファイルでもビュワーとして
  使える旨を含む文言に更新する。
- 各カードの説明文（例：「2つのDBの同名テーブルを、複合キーで行対応付け
  してセル単位に比較。…」）も、「1つならビュワー、2つなら比較」に触れる
  形に更新する。
- 各ツール画面上部のサブタイトル（例：excel-diff.htmlの「2つの .xlsx を
  シートごとにセル比較」）も同様に、1ファイルのみでも閲覧できる旨に更新
  する。

## 実装上の既知の制約（既存ロジック流用に伴うもの）

既存の比較計算・描画ロジックをそのまま流用する方針を取るため、以下は
「ビュワーとして完全に理想的」ではないが許容する挙動として明記する。

- **Word**: 内部的には1ファイルのみでも `JsDiff.diffLines` を実行する
  （読み込まれていない側に同じテキストを与えるため、結果は必ず全行
  一致になり、見た目としては差分ハイライトのないプレーンテキスト表示
  になる）。「diff処理をそもそも行わない」わけではない。極端に大きい
  文書ではdiff計算のコストが残るが、既存の2ファイル比較時と同等の
  コストであり許容する。
- **Word**: 本文の行分割に既存の `lines()` 関数（空行を除去する仕様）
  を流用するため、元文書の空段落はビュワー表示でも失われる。これは
  既存の差分表示と同じ制約であり、今回のスコープでは変更しない。
- **Access**: 単一ファイル表示でも、内部的には列の先頭列が自動的に
  「キー列」として扱われる（既存の複合キー自動選択ロジックをそのまま
  流用するため）。UI上はキー列選択フィールドを非表示にするが、行頭の
  ステータス記号（`=`）やキー列バッジ（`KEY`）はテーブル内に残る。
  並べ替えプルダウンの選択肢にある「キー列で並べる」という項目名も
  そのまま残る（並べ替え機能自体はキー列に関わらず動作するため実害は
  ない）。これらは許容する。
- **Excel/Access**: 表示行数の上限（Excel 4000行、Access 6000行）は
  単一ファイル表示でも既存の上限処理をそのまま適用する。
- **PDF出力**: 空シート・0件レコード・空文書など、既存ロジックで
  PDF出力ボタンが無効になるケースは単一ファイル表示でも同様に無効の
  ままとする（例外を設けない）。
- **空データケース**: 読み込んだファイルにシート/テーブルが1つも
  存在しない場合に表示するメッセージは、単一ファイルモード用に
  文言を出し分ける（比較を前提にした「同名シートがありません」等の
  文言をそのまま出さない）。

## テスト方針

- 手動確認（ブラウザで実ファイルを使用）:
  - Excel: ファイルAのみ登録し、複数シートを持つブックで各シートが
    タブ切り替えで通常表示されること。差分色が付かないこと。結合セル
    を含むシートで結合がそのまま表示されること（`diffOnly` の前回値が
    Cookieに残っていても結合表示が壊れないこと）。PDF出力が機能する
    こと。その後ファイルBを追加し、既存の差分比較に自動で切り替わる
    こと。
  - Access: ファイルAのみ登録し、複数テーブルを持つDBでテーブル切替・
    ソートが機能すること。差分色が付かないこと。ファイルBを追加後に
    既存の差分比較へ切り替わること。
  - Word: ファイルAのみ登録し、本文がそのまま表示されること（差分ハイ
    ライトなし、折りたたみなし）。ファイルBを追加後に既存の差分比較へ
    切り替わること。
  - 逆にファイルBのみを先に登録した場合も同様に動作すること（ページを
    再読み込みしてファイルBのみを読み込む）。
  - Cookie/localStorageによる設定復元（シート・テーブル選択、手動ペア
    モード、並び順等）が1ファイルのみの状態でも、チェックボックス等の
    見た目と内部状態が食い違わないこと。
  - 3ツールとも、2ファイル揃った状態での既存動作（同名なし・手動ペア・
    読込失敗時のエラー表示等）に回帰がないこと。
